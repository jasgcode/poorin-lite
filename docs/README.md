# Project docs

This directory holds the project's context: the decisions that shaped the code, the experiments
run and what each concluded, and the designs behind larger changes. [`index.md`](index.md) lists
every file, open experiments first; read it before starting a task and open only the files it
points to.

```
docs/
  index.md                      generated by `uv run python -m repro.docs`; never edit it
  decisions/NNNN-<slug>.md      one choice between options
  experiments/<slug>.md         one question, across all the runs that answer it
  designs/YYYY-MM-DD-<slug>.md  a spec (-design.md) or an implementation plan (-plan.md)
```

A slug is lowercase letters, digits, and hyphens. Results live in `repro`'s records: an
experiment's conclusion cites runs and evaluations by `name@version`, and does not copy metrics
tables.

## Headers

Every file starts with a YAML header of three fields. `index.md` is built from them, and
`uv run python -m repro.docs --check` (run by the test suite) fails when one is invalid or the
index is stale.

| Field | Rule |
|---|---|
| `date` | `YYYY-MM-DD`: the day the decision was made, the experiment opened, or the design written |
| `status` | decisions: `adopted` or `superseded`; experiments: `open` or `closed`; designs: none |
| `summary` | one line, at most 120 characters |

## Decisions

Add one when a change chooses between options, in the same commit as the change. Number it one
past the highest in `decisions/`.

```markdown
---
date: 2026-10-18
status: adopted
summary: Muon is the default optimizer
---

# 0002. Muon is the default optimizer

## Decision
## Why
## Alternatives
## Cost if wrong
```

Never rewrite a past decision. To reverse one, add a new decision that names the one it replaces,
set the old one's status to `superseded`, and add the line `Superseded by [0007](0007-<slug>.md).`
to it.

## Experiments

An experiment is a question. Open its file before its first run, and launch every run for it with
`--experiment <slug>`; the launcher refuses a slug with no file here, or a closed one, and records
the slug in each run's provenance. `uv run python -m repro.experiment.runs list --experiment
<slug>` lists its finished runs.

```markdown
---
date: 2026-10-17
status: open
summary: Does Muon beat Adam at 100M parameters?
---

# Does Muon beat Adam at 100M parameters?

## Question
## Log
### 2026-10-17
## Conclusion
```

- `Question`: the hypothesis and how it will be decided.
- `Log`: dated entries, appended and never edited: what was run, what was seen, what to try next.
  Name runs by `name@version`, including runs reused from other experiments.
- `Conclusion`: the answer, citing runs and evaluations. When it is written, set `status: closed`
  and replace `summary` with the answer, so the index reads as results. A dead end closes too, and
  says why it stopped.

## Designs

Specs and implementation plans, free-form below the header (which has no `status`). Name a spec
`YYYY-MM-DD-<slug>-design.md` and its plan `YYYY-MM-DD-<slug>-plan.md`.
